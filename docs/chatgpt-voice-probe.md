# Ранняя озвучка ChatGPT на Станции Лайт 1: локальная проба

Экспериментальная сборка для Linux ARM64 с чистого upstream `08acdf5`. Использует уже настроенный `mode: hybrid`, `llm_api: chatgpt` и существующий вход по подписке. Параллельные доработки перебивания и MCP OAuth в сборку не включены.

Только обращение **«Тест потока, …»** в режиме эксперимента запускает обычный текстовый запрос к модели без инструментов и веб-поиска. В режиме `early` мост озвучивает первое законченное предложение, затем остаток подтверждённого ответа. Это проверка времени старта, а не непрерывная озвучка каждого предложения. Без подходящих текстовых событий, при разметке в первой фразе или отсутствии границы предложения мост ждёт полного ответа. В режиме `baseline` точно такой же запрос всегда ждёт конца. По умолчанию оба экспериментальных режима выключены.

## Подготовлено на ПК

- `dist/chatgpt-voice-probe-arm64.tar.gz`, рядом `.sha256`. Это штатный формат standalone-пакета с экспериментальным исполняемым файлом.
- Офлайн-проверка: `go test -race ./internal/bridge -run 'TestChatGPTProbe|TestProbe' -count=1`. Тест проводит запрос через `Native → Engine → ChatGPT Responses` с искусственным HTTP-транспортом. Тест удерживает `response.completed` до получения байтов первой речи на выходе к колонке. Проверяются ответы TTS с событием `TtsSpeak` и без него, повторное использование номера аудиопотока, отсутствие повтора в полях Text/Voice и закрытие без остатка.
- Пересборка: `python3 scripts/build-speaker-package.py --arch arm64 --output dist/chatgpt-voice-probe-arm64.tar.gz` (Go из `go.mod`).

## На колонке, **когда она освободится**

Пример для уже работающего standalone Bridge в `/data/opt/quasar-bridge`, с уже переключённым на него голосовым трафиком. Если параллельная задача оставила иной способ запуска, верните её в исходное состояние или согласуйте способ остановки с её владельцем. Перед пробой исходный `control.sh status` должен успешно распознать работающий процесс.

1. Перенесите архив и `.sha256` в **новый** каталог на разделе `/data`, например `/data/opt/chatgpt-voice-trial`. В shell колонки:

   ```sh
   STATE=/data/opt/quasar-bridge
   TRIAL=/data/opt/chatgpt-voice-trial
   OLD=$STATE/app
   export QUASAR_DATA_DIR="$STATE"
   cd "$TRIAL" || exit 1
   uname -m                         # aarch64 или arm64
   df -h "$TRIAL"                   # хватит места для архива и распакованного ELF
   sha256sum -c chatgpt-voice-probe-arm64.tar.gz.sha256 || exit 1
   mkdir probe && tar -xzf chatgpt-voice-probe-arm64.tar.gz -C probe || exit 1
   PROBE=$TRIAL/probe
   sh "$OLD/control.sh" status && sh "$PROBE/control.sh" check || exit 1
   ```

   Если `check` не принимает конфигурацию более новой сборки, остановитесь здесь: работающий процесс ещё не тронут. Файлы `config.json`, `runtime.env` и ChatGPT OAuth переносить или редактировать не требуется. `install.sh`, `apply`, `rollback` и перезагрузка для этой пробы не используются.

2. Сделайте контрольный замер. Только после успешных проверок выше:

   ```sh
   sh "$OLD/control.sh" stop || exit 1
   QUASAR_CHATGPT_VOICE_PROBE=baseline sh "$PROBE/control.sh" start || {
     sh "$OLD/control.sh" start
     exit 1
   }
   ```

   Произнесите: **«Алиса, тест потока, начни словами „Поезд отправился.“ и расскажи историю про поезд в восьми коротких предложениях»**. Засеките время от конца вопроса до первого *слышимого слова* и дождитесь окончания. В журнале должен быть `native_route_decision` с `source=chatgpt_voice_probe`; иначе сравниваются разные маршруты.

3. Включите ранний старт **в той же сборке** и повторите тот же вопрос. При повторном старте процесса история диалога в памяти начинается заново.

   ```sh
   QUASAR_CHATGPT_VOICE_PROBE=early sh "$PROBE/control.sh" restart
   ```

   Проверьте: первая фраза звучит один раз; история продолжается, заканчивается, следующее обращение работает. Для чистого сравнения задавайте вопросы по одному. Желательно сравнить по три прогона каждого режима. Журнал:

   ```sh
   grep 'chatgpt_probe_' "$STATE/service.log" | tail -40
   ```

   Для одного `request` сравните `ms`: `chatgpt_probe_first_tts` — запрос на синтез первой фразы, `chatgpt_probe_first_audio_rx` — первые речевые пакеты от синтезатора, `chatgpt_probe_complete` — завершение запроса к модели. Отсчёт начинается после выбора маршрута. `first_audio_rx < complete` показывает перекрытие синтеза и генерации; услышанное время проверяется отдельно. Если есть только `complete`, ранней озвучки в этом запросе не было. `chatgpt_probe_tail_mismatch` означает, что подтверждённый текст отличался от уже произнесённого начала: прототип не зачитывает ответ с начала.

4. **Вернуть исходный Bridge**, в том числе если звук завис или сравнение прервано:

   ```sh
   sh "$PROBE/control.sh" stop && sh "$OLD/control.sh" start && sh "$OLD/control.sh" status
   ```

   В новом shell подставьте абсолютные пути `/data/opt/chatgpt-voice-trial/probe` и `/data/opt/quasar-bridge/app`. Исходный каталог программы, загрузочный хук и адрес сервера в прошивке при таком запуске не заменяются.
